### The standing rules this project learned the hard way

- **Verify against the installed source and the live system, never against docs, `npm audit`'s "fix available", or a previous session's conclusion.** The highest-value fixes here (security headers, the `/api/quote` limiter, the `users.unlock` gate, the silent no-op migrate step, the non-deterministic axe gate, the unsent password-reset email) were all found by re-reading code or running the product after a session had concluded "everything remaining is externally gated".
- **A passing CI step must prove its post-condition** (the migrate step "passed" for six weeks while applying nothing).
- **Prove a regression test fails without its fix**, both directions, before trusting it.
- **A comment in `.env` is not a guard; a process that refuses to start is** (`src/lib/dbGuard.ts`).
- **Any client-side navigation across an authorisation boundary must be a hard navigation** (`window.location.assign`) — the App Router's client cache replays prefetched redirects.
- Deploy through CI (Ubuntu), never `sst deploy` from Windows; `npm ci` before any local build; `npm run devsafe` after a `proxy.ts` change.

### Admin password reset, Payload CSRF allowlist, header hardening — 2026-09-16/17, commit `bd38da4`

**Found by reading, not by the roadmap.** FUNCTIONALITY §5.1 / TECHSPEC §6.6 said the admin "receives a reset link by email … via SES". Verified against the installed `payload@3.89.0` source, none of it existed:

1. No `email` adapter → Payload's console adapter logs *"Email attempted without being configured"* and returns success. "Forgot your password?" showed *Email Sent*; nothing was sent. One admin + mandatory 2FA = an unrecoverable password without DB access.
2. No `serverURL` → `utilities/getRequestOrigin.js` refuses the Host header (correct — host-header injection) and returns `''`, so even with an adapter the reset link would have been the relative `/admin/reset/<token>`.
3. No `serverURL`/`csrf` → `csrf = []`, and `auth/extractJWT.js` accepts the `payload-token` cookie from **any `Origin`** when the list is empty. Payload's CSRF allowlist was disabled; SameSite=Lax was the only defence. (Payload's docs imply the opposite; the source is what runs.)

**Built (no new dependency, no schema change):**
- `src/lib/email/payloadEmailAdapter.ts` — a Payload `EmailAdapter` bridging onto the existing SES v2 path (`ses.ts`): execution-role auth, the verified `bulbau.lu` identity, never throws. Not configured outside production → prints the message (incl. the reset link) to the server console so the flow is completable locally; not configured in production → one `OPS_ALERT` (`email.payload.notConfigured`), body never logged. Chosen over `@payloadcms/email-nodemailer` (SES SMTP = a new long-lived secret) and Resend (a new sub-processor).
- `src/lib/email/resetPasswordEmail.ts` — branded mail per the OWASP Forgot Password cheat sheet (link only, expiry stated, "ignore if not you", everything escaped).
- `src/lib/serverUrl.ts` — `resolveServerUrl()`: `NEXT_PUBLIC_SITE_URL` (the `SiteUrl` secret) → else `https://bulbau.lu` **only on the SST production stage** → else `http://localhost:3000` outside production mode → else `''`. A staging stage without `SiteUrl` keeps the old permissive behaviour and logs a loud warning instead of locking its admin out; a CI `next build`/`next start` is never mistaken for production (`readSstStage()` has no `NODE_ENV` fallback). Payload's sanitizer copies `serverURL` onto `csrf`, so exactly one origin is trusted.
- `Users.ts` — 1-hour expiry explicit, branded subject/HTML built from the **configured** origin only, and a **rate limit on `/api/users/forgot-password`** (5 / 15 min per IP *and* per address, via the shared limiter, before the account lookup — it was an unauthenticated SES-send trigger with no cap).
- `next.config.ts` `poweredByHeader: false` — production served `x-powered-by: Next.js, Payload` (OWASP: remove). `withPayload` honours the flag.
- `src/proxy.ts` — the security header set is applied to **proxy-terminated redirects** (`/` → `/en`, the admin gate's `/admin/totp-verify`); `next.config` `headers()` never sees those, and `curl -I https://bulbau.lu/` was a bare 307. Only on 3xx, so nothing is emitted twice.
- Careers "Contact Us" CTA → `/contact` (it still pointed at `/about`); the leftover `tsconfig.check.json` removed.
- `.env.example`: `NEXT_PUBLIC_SITE_URL` is now also Payload's `serverURL`; `EMAIL_SENDER` also feeds the reset mail.

**Tests:** `tests/int/emailAdapter.int.spec.ts` (resolver, template, adapter branches, and the real `forgotPassword` operation against Postgres: absolute link = stored token, uniform no-enumeration response, 429 on the 6th call); `rest.int.spec.ts` gained the CSRF cases (foreign `Origin` → anonymous; no `Origin` + `Sec-Fetch-Site: same-origin` → accepted; neither → rejected; `unlock` from a foreign origin → 403) — cookie-bearing test requests now carry `Origin`, as a browser does; `tests/e2e/accountRecovery.e2e.spec.ts` (the forgot screen reaches "Email Sent", the 429, `/me` with a fully verified session from a foreign origin is `{ user: null }`, the gate redirect carries the headers) — both rate-limit keys unique per run so a re-run cannot poison the dev server's 15-minute window; `securityHeaders.e2e` asserts the `/` redirect and the absence of `x-powered-by`.

Browsers send no `Origin` on same-origin GETs, so Payload falls back to `Sec-Fetch-Site`; CloudFront forwards it (managed `AllViewerExceptHostHeader`), while `X-Real-IP`/`Referer` are on CloudFront's removal list. ### Phase 5 part 1 — auto-translation — 2026-08-02

**AWS Translate, not DeepL** (DeepL's recurring free tier is gone; Translate authenticates via the execution role — no secret, no new sub-processor, FORMAL register). A **synchronous `afterChange` hook**, not the Jobs Queue (Payload's `autoRun` is not for serverless; Next's `after()` is unsupported on OpenNext). Because `afterChange` runs inside the save transaction, a timeout there rolls the publish back — hence: calls paced at ~16/s under the 20 req/s quota (no throttle → no backoff), a hard 12 s deadline under an explicit 30 s Lambda timeout, never throws, locales sequential (one transaction), and a recursion guard that **mutates `req.context.skipAutoTranslate`** (the per-call `context` argument did not reach the nested hook → the "3-minute create"). Field selection is self-healing and override-safe: (re)translate iff the EN source changed or the target still equals the EN fallback, read at the same depth. `src/lib/translation/registry.ts` is the hand-kept list of localized paths (a registry↔schema drift test is still a good hardening item).

### CI hardening slices — 2026-07-21

- **Security headers** (`src/lib/security/headers.ts`, one source of truth for config and tests): HSTS 2 y + `includeSubDomains` (no `preload` yet), `nosniff`, `Referrer-Policy`, `X-Frame-Options`, `X-XSS-Protection: 0`, `Permissions-Policy`, COOP, and a **nonce-free CSP** (`base-uri`, `object-src`, `frame-ancestors`, `form-action`; deliberately no `default-src`/`script-src` — a nonce CSP would silently break the Payload admin).
